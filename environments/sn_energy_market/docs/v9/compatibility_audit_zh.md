# 统一运行接口、旧兼容清理与关键校验审查

**日期：2026-10-18。结论：运行时只保留当前一套环境接口，旧机制兼容入口已清理；最新 207 项测试及专项批量验证通过。**

## 1. 接口统一与兼容入口清理

| 修改位置 | 发现或原有情况 | 本次处理 |
|---|---|---|
| `contracts.py`、包导出 | 通用动作名称曾指向带版本后缀的类型；旧消费者四个位置参数能落入新字段 | 统一定义 `UCAction`、`ConsumerAction`，不提供版本别名；两个动作类均使用关键字参数构造 |
| `action.py` | 对象、向量的构造入口 | 六维／四维数组按当前物理字段转为具名对象；不调用旧解码器 |
| `validation_helpers.py`、测试 | 调用带版本后缀的动作类或使用位置参数 | 全部使用统一类型和明确字段名 |
| `PublicOffer` | `der_available_kw`、`uc_available_kw` 旧字段别名 | 删除；分别使用 `der_capacity_kw`、`uc_capacity_kw` |
| `PhysicalExecution` | `der_curtail_kw` 旧字段别名 | 删除；明确区分主动弃电、未售 DER、总弃电 |
| `reserve.py` | 保留了只抛异常的旧备用入口 | 整个模块删除，运行链不导入备用模块 |
| 旧订单与执行类型 | 原备用与普通调度结构 | 不提供 `DRRequest`、`RegularDispatch`、`Fulfillment` |
| 配置 | 旧 UC 报价、备用、自放电、旧奖励与嵌套字段 | 入口直接拒绝，不翻译成当前规则、不忽略字段 |
| 快照 | 历史规则和数据签名 | 版本、配置、数据不匹配时拒绝恢复，原状态保持 |

类型名称不含建模文档版本。当前规则仍通过配置、快照和验证元数据标识，以检查保存的数据是否适用。

对象构造示例：

```python
from snmarket import ConsumerAction

action = ConsumerAction(
    curtail_kw=0.0,
    signed_shift_kw=0.0,
    der_preference_fraction=0.5,
    der_bid_per_kwh=0.3,
)
```

四维裸向量没有来源版本，接口固定解释为当前四个物理字段。调用方必须明确其语义；环境不猜测旧 UC 报价，也不将旧轨迹自动转换为新动作。旧策略、旧观测和旧训练 checkpoint 需要重新接入。

历史建模文档及旧验证报告作为研究记录保留，不导入生产环境。生产市场、物理执行、费用和奖励没有回退到旧机制的分支。

## 2. 关键校验与精简内容

校验集中在输入边界和唯一提交之前。内部计算接收已校验的数据对象。

| 精简位置 | 调整 | 保留的关键检查 |
|---|---|---|
| UC 公告 | 删除引擎对同一个动作的第二次校验 | `prepare_offer` 校验六维联合域后发布公告 |
| 市场 | 删除已在订单与公告入口验证的数值重复判断，删除末尾重复总成交断言 | 重复消费者 ID 拒绝；提交前统一检查总服务与公告容量 |
| 结算 | 直接返回现金、费用与残差，删除内部重复抛错 | 引擎检查奖励有限及资金闭合，失败时不提交 |
| FIFO | 删除未使用的截止桶函数、重复回补和到期恒等式判断 | 个人服务上限、实际任务更新、提交前队列守恒 |
| 观测截止桶 | 删除与状态入口相同的期限判断 | 状态入口检查期限范围；观测检查 float32 可表示性 |
| 旧备用模块 | 删除仅用于拒绝旧调用的模块 | 旧模块不可导入 |

相对首次迁移源码，共移除 11 处重复或废弃的 `raise` 分支；UC 重复调用另外合并。配置合法性、非有限输入、物理/SOC 边界、阶段、原子提交、重复结算和快照一致性继续检查。对现金、队列和市场结果分别注入错误的测试确认：异常候选不会改变状态。
