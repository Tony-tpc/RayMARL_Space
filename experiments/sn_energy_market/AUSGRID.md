# Ausgrid 真实数据实验

本实验将 Ausgrid 的住户总用电和光伏实测序列接入现有能源市场，使用 30 分钟步长。数据转换、场景配置、时间划分与验证入口均位于 `experiments/sn_energy_market`；算法继续使用通用场景工厂接口，市场内核继续接收 `Profiles`。

## 1. 数据来源和下载核验

数据发布者是 **Ausgrid**。澳大利亚政府 [data.gov.au 目录](https://data.gov.au/data/dataset/nsw-solar-home-electricty-data)及其 [CKAN 元信息接口](https://data.gov.au/data/api/3/action/package_show?id=nsw-solar-home-electricty-data)列出数据名 Solar Home Electricity Data 和 **CC BY 3.0 Australia** 许可。

原官方下载页已失效，使用 [Pierre Haessig 数据分析仓库](https://github.com/pierre-haessig/ausgrid-solar-data)明确发布的[完整归档副本](https://pierreh.eu/downloads/Ausgrid_solar_home_data.zip)。这是原始数据的第三方归档，下载来源和发布者分别记录。代码固定该归档的 SHA-256：

```text
5a766f52b6c8b3b72730380f4422e478934bc94640a4b089dd0e0e3c055c5d82
```

完整归档为 57,038,633 字节。另从 [独立镜像](https://github.com/rockey-abhishek/Ausgrid-Dataset)取得原说明 PDF 和 2012—2013 原始 CSV，逐字节哈希与主归档比对；CSV 哈希为：

```text
e4be46b3c9991c65735a9545319a2f1c33be8e639c75a17a88e0323a8e5098be
```

原文件和来源证据保存于 `datasets/ausgrid/raw/`，处理后文件保存于 `datasets/ausgrid/processed/`。两者沿用项目的数据目录排除规则，不进入 Git；代码、协议及验证摘要进入 Git。再次运行下载入口时使用本地缓存，主归档哈希不符即停止处理。

署名：Ausgrid, *Solar Home Electricity Data*, 2010–2013, released 2014，CC BY 3.0 Australia；归档镜像由 Pierre Haessig 维护。本项目的转换包括完整住户筛选、GC 与 CL 合计、电量转功率，以及名义日历的区间起点标记。

## 2. 清洗规则与固定住户

原数据包含 300 户。三年记录完整、值有限且非负、计量质量合格、邮编和装机元信息一致的住户共 255 户。默认从合格户数最多的邮编开始，邮编同序时按邮编排序，同邮编内按住户 ID 排序，取前 16 户。

当前 16 户均属于邮编 **2259**，固定顺序如下：

```text
7, 19, 20, 29, 30, 38, 49, 64,
67, 84, 106, 155, 160, 169, 177, 184
```

该顺序固定对应 `consumer_0` 至 `consumer_15`。逐户排除原因保存在清单 `quality_audit.households`，包括缺日、重复通道日期、非实际计量标记及元信息变化。

- `GC` 为不含 CL 的普通消费，`CL` 为单独计量的受控消费，`GG` 为总光伏发电。
- 三者原始单位均为每半小时 kWh。`loads_kw=(GC+CL)/0.5`，`pv_kw=GG/0.5`，共享 `der_kw` 为所选住户光伏功率之和。
- 只有三年完全没有 CL 通道的住户才将 CL 记为零。出现过 CL 但部分日期缺失的住户不纳入固定面板。
- 原始 `Row Quality` 中的字面值 `NA` 表示非实际计量信息，不作为空字符串。读取时禁用 pandas 默认 NA 识别，非空质量标记均排除。原验证年和测试年分别发现 100、431 条非空质量记录。
- 不插补缺测，不裁剪尖峰，不把 30 分钟插值成 15 分钟。对选中住户逐年核对原始电量与处理后功率积分。

住户可用性筛选查看三年的完整性与质量信息，以构造同一批用户的固定面板；PG、ESS、DR 和队列的数值标定仅使用训练年。验证／测试年的负荷大小、策略收益与模型表现不参与选户排序或参数拟合。

## 3. 时间与集合划分

原表头从 `0:30` 到下一日 `0:00`，表示区间结束。本项目输出对应区间开始时刻，从当日 `0:00` 到 `23:30`。

原说明同时提到 EST／EDT，而每日固定 48 列，无法唯一重建夏令时切换日的真实 UTC 时刻。因此使用 **固定 +10 的名义仿真日历**：保留全部原始日期、48 时段顺序和电量，不删除或补造时段。清单记录六个夏令时切换日期和这一时间口径。当前配置费率按该仿真日历执行；与外部真实现货价格配对前需另做时间对齐。

| 集合 | 日期（右端不包含） | 半小时时段 | 月场景 |
|---|---|---:|---:|
| 训练 | 2010-07-01 至 2011-07-01 | 17,520 | 12 |
| 验证 | 2011-07-01 至 2012-07-01 | 17,568 | 12 |
| 测试 | 2012-07-01 至 2013-07-01 | 17,520 | 12 |

先确定年度集合，再切完整月份。2012 年闰日自然保留。三个集合分别使用种子起点、起点加 10,000、起点加 20,000，均覆盖全部 12 个月。`train.py` 为训练月设置 1 日、11 日、21 日和最后一日四个起点，共 48 个场景；按全年月份与月内日期交替遍历。验证和测试仍各为 12 个月初场景。

一个月对应一个有限时域，月初采用空任务队列、零月累计和配置初始 SOC，月末按既有终端规则结算。月中训练状态由月初起的固定规则回放构造：UC 使用全部 PG 公告、不开储能、不主动弃电、不采购 DR；消费者不削减、不移峰、先申购 DER 并采用报价底价。回放保留真实月累计 UC 用电和历史记录，不进入学习批次；真正终止仍在月末。该起点分布显式记录于合同，后续学习轨迹中的队列、SOC 和累计电量正常演化。`DatasetEnvFactory` 的独立默认设置仍为月初，调用方通过 `training_start_days` 选择训练日期。

训练采样每 64 步截取一个片段，片段末尾保留环境状态并估计后续价值；这不构成环境终止。最后 24 小时按模型原有规则关闭新的移出任务。

## 4. 30 分钟参数与资源配置

| 项目 | Ausgrid 默认设置 | 依据 |
|---|---:|---|
| 步长 | 30 分钟，即 0.5 h | 原始测量分辨率 |
| 移峰期限 | 48 步 | 保持 24 小时 |
| DR 事件 | 每日 `[34,40)` | 保持 17:00—20:00 |
| 折扣 gamma | 0.9801 | `0.99**2`，保持相同物理时长折扣 |
| GAE lambda | 0.9025 | `0.95**2`，保持相同物理时长衰减 |
| 默认采样长度 | 64 步 | 保持 32 小时 |
| UC 到期考核系数 | 2.00 | 持续逾期按步考核的小时等价换算 |
| 按 kWh 收费和按 kWh·h 计费的系数 | 保持原值 | 结算已经按各自量纲处理时长 |
| 每期固定外部金额 | 保持原值，默认零 | 本期金额不自动解释为每小时费用 |

默认从训练年社区总负荷计算 Q95，得到 **20.7504 kW**。场景资源配置为：

| 参数 | 数值或规则 |
|---|---|
| PG 额度 | 20.7504 kW，即训练负荷 Q95 |
| ESS 充／放功率 | 各 5.1876 kW，即 Q95 的 25% |
| ESS 容量 | 10.3752 kWh，可按额定功率运行 2 小时 |
| 初始 ESS 电量 | 5.1876 kWh，即 50% SOC |
| DR 采购上限 | 4.15008 kW，即 Q95 的 20% |
| 每户柔性能力 | 当期负荷的 20% |
| 每户队列容量 | 24 h × 训练年个人柔性功率 Q95 |

这些是明确的实验配置，不是数据中实测的设备容量或消费者意愿。共享光伏保留所选住户的实际总发电，不另行放大。使用 `--config-dir` 时，保留用户指定的 PG、ESS、DR 与队列容量，只协调时间步长、日期、人数及相应持续时间参数。

价格采用场景分时采购费率：17:00—22:00 为 0.65，其余时段 0.35；单位统一为 AUD/kWh，其余金额系数在本实验中也统一解释为 AUD 场景参数。消费者阶梯价沿用模型结构。这些费率不声称来自 Ausgrid 实测或澳洲真实零售合同。

## 5. 复现入口

在项目根目录执行。数据预处理额外依赖由本目录 `requirements-data.txt` 声明，不增加算法包依赖。

```powershell
.\.venv\Scripts\python.exe -m pip install -r experiments/sn_energy_market/requirements-data.txt
.\.venv\Scripts\python.exe -B -m experiments.sn_energy_market.ausgrid
```

已有原始数据时，可离线重建：

```powershell
.\.venv\Scripts\python.exe -B -m experiments.sn_energy_market.ausgrid --no-download
```

只验证数据、配置和 36 个月场景构造，不导入训练运行时：

```powershell
.\.venv\Scripts\python.exe -B experiments/sn_energy_market/train.py --dataset datasets/ausgrid/processed/manifest.json --validate-data --output outputs/ausgrid-validation/interface
```

逐月执行真实环境，核对每期账目与物理约束，并测试未训练网络的采样接口：

```powershell
.\.venv\Scripts\python.exe -B experiments/sn_energy_market/validate_dataset.py --dataset datasets/ausgrid/processed/manifest.json --output outputs/ausgrid-validation/full
```

`validate_dataset.py` 不创建 Learner、不更新网络参数。它覆盖三年 36 个完整月场景，每期校验功率、SOC、队列、资金、奖励和观测，每日抽取时段与独立参考计算比较，并检查快照重放。另连续采样两个 64 步神经网络批次，检查概率、优势和价值目标有限且参数完全未变。

`ProfileDataset` 负责文件、单位、连续日期和月窗口；`DatasetEnvFactory` 满足现有通用场景工厂接口。检查点合同绑定数据与代码哈希、住户顺序、月份、配置和场景价格。`RLAlgo` 与环境内核均无需数据集专用分支。

## 6. 本轮验证结果

2026-10-19 完成以下验证；汇总证据见本目录 `ausgrid_validation.json`，逐月完整结果位于 `outputs/ausgrid-validation/full/`。

| 检查 | 实际完成量／结果 |
|---|---|
| 环境、实验接口和相关算法回归测试 | 278 项通过；6 项原生训练／CUDA 集成测试未运行 |
| 真实数据完整月轨迹 | 36 个月，52,608 个物理时段 |
| 逐户账目与队列检查 | 841,728 个消费者时段 |
| 独立数值参考对照 | 1,168 个完整时段 |
| 公告后快照重放 | 36 次结果完全一致 |
| 未训练网络采样 | 17 个 Agent、两个 64 步批次；网络参数完全未变 |
| 实际完整数据再次清洗 | 四个处理产物的 SHA-256 均完全一致 |
| 静态检查 | Ruff、格式检查和 Git diff 检查通过 |

功率平衡和现金账目的最大绝对残差均为 `7.11e-15`，独立参考计算的最大绝对残差为 `7.11e-15`，队列能量残差为 `3.38e-15 kWh`。原始电量与处理后功率积分的最大残差为 `1.46e-11 kWh`。所有差异均在明确的双精度容差内。

接入审查修正了质量标记 `NA` 被默认空值解析吞掉、自定义资源被默认标定覆盖、每期固定金额被误作小时费率换算、以及运行时间字段导致清单哈希变化的问题。最终数据合同保留来源、计量单位、时间口径、身份顺序和代码哈希。

本轮未启动正式训练，也未修改算法实现和环境内核。实测曲线验证了数据与执行链路；场景柔性比例、采购费率和资源配置仍按第 4 节的实验假设使用。
